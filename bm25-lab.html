第 0 步 · 我们的小语料库(8 篇超短文档)

检索就是:给定一个查询,从这堆文档里挑出最相关的。下面高亮的是命中查询词的位置。

第 1 步 · 最朴素的想法:数数(TF 词频)

直觉:查询词在一篇文档里出现得越多,这篇越相关。那就数呗。
TF = Term Frequency = 词频:某个查询词,在某篇文档里出现了几次。就是数数。

第 2 步 · 修第一个毛病:稀有的词更值钱(IDF)

"吃"到处都是,命中它说明不了什么;"鱼"很少见,命中它信息量大。该按稀有度加权。
DF = Document Frequency:有几篇文档出现过这个词(注意:是"几篇",不是"几次")。
IDF = Inverse DF = 逆文档频率:DF 的"反过来"——出现的文档越少,IDF 越大(越值钱)。
IDF(词) = ln( (N+1) / (df + 0.5) ) + 1
　　　　　N = 文档总数 ,　df = 含这个词的文档篇数 ,　ln = 自然对数

第 3 步 · 修第二个毛病:出现 5 次 ≠ 相关 5 倍(饱和 k1)

一篇文档把"猫"刷了 5 遍,它真比只提 1 次的相关 5 倍吗?不。该让分数涨到一定程度就"封顶"。
饱和(saturation):出现次数 tf 越大,加分越多,但越加越慢,最后逼近一个上限。控制这个"涨多快、封多高"的旋钮叫 k1。
把光秃秃的 tf,换成会饱和的版本:
　饱和后 = tf × (k1+1) / ( tf + k1 )　　(先不管长度,下一步再加)

第 4 步 · 修第三个毛病:长文档占便宜(长度归一化 b)

长文档天生词多、更容易命中。一篇 18 个词的文章里有"鱼",不该和一篇 3 个词的短句里有"鱼"一样值钱。该按长度打折。
avgdl = average document length:所有文档的平均长度(平均多少个词)。
一篇文档比平均长 → 分母被撑大 → 同样的命中打折扣;比平均短 → 反而加成。旋钮叫 b(b=0 完全不管长度,b=1 狠罚)。
完整分母(把长度塞进 k1 那项里):
　分母 = tf + k1 × ( 1 − b + b × 文档长度 / avgdl )

第 5 步 · 四块积木合体 = 完整 BM25

把 IDF(稀有度)× 饱和后的 TF(带长度罚)合起来,一个查询词一项,加总 = 这篇文档的 BM25 总分。
BM25(文档 D, 查询 Q) = 对查询里每个词 t 求和:
　Σ　IDF(t) × tf × (k1+1) / ( tf + k1 × (1 − b + b × L/avgdl) )
　　　└稀有度┘　└──── 饱和的词频 ────┘　　└─ 长度归一化 ─┘
　　　tf = 词 t 在 D 里的次数 ,　L = D 的长度 ,　k1=饱和 ,　b=长度罚

这就是关键词召回(BM25)的全部。没有向量,没有训练,纯统计:数词频 → 按稀有度加权 → 防刷词饱和 → 按长度打折 → 加总排名。它的死穴:只认字面——查"掉线"它绝不会去命中"网络中断"(在它眼里是完全不同的词)。这正是为什么要再叠一路稠密向量来补语义,合起来就是混合检索。
