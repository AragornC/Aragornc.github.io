① 数据层:每条 chunk 存成一条「记录」

这是索引之前最基础的存储。每条记录 = id + 原文 + 元数据 + 向量。向量来自上一阶段的 embedding。
存储形态(一条记录的真实样子)

② Flat:其实没有"索引"

最简单——啥额外结构都不建,就把所有向量并排放成一个大数组。构建 = 零。
Flat 存的索引结构
就一个 N×512 的矩阵。检索时逐个比(但那是检索的事,这里不演)。

③ IVF 构建:k-means 分簇 → 建倒排表

构建两步:(1) k-means 把向量分成 C 簇、得到 C 个簇心;(2) 建「倒排表」记录每个簇里有哪些向量 id。
构建过程
IVF 存的索引结构(簇心 + 倒排表)
倒排表 = 簇 → [向量id列表]。这就是 IVF 落进库里的东西(+ 上面的数据层记录)。

④ HNSW 构建:逐点插入 → 连边成图

构建 = 一个个插入向量,每个新点连到「已插入点中最近的 k 个」(双向)。早插入的点散布全局形成长链。结果是一张「邻接表」。
构建过程(逐点插入,连了哪些边)
HNSW 存的索引结构(邻接表 = 每个点连到谁)
邻接表 = 节点id → [邻居id列表] + 入口点。这就是 HNSW 落进库里的图。

⑤ PQ 编码:把 512 维向量压成几个字节

构建:把每段子向量用 k-means 学一本小字典(原型)。存储:每个向量 → 每段记"最近的原型编号"。看一条向量被压成啥。
