① 来源:谁、何时、为什么造它

谁做的:由 Jeff Huber(CEO)和 Anton Troynikov 共同创立的公司 Chroma(trychroma.com) 开发。2023 年 4 月拿到约 1800 万美元种子轮融资(由 Quiet Capital 领投)。它是一个有公司在背后全职维护的开源项目,GitHub 上是 chroma-core/chroma。

什么时候开源:项目 2022 年 10 月首次开源(第一次提交在 2022 年 10 月初)。属于 LLM 应用爆发期最早一批专门为「给大模型喂资料」而生的向量库。

为什么造它(解决什么痛点):2022 年做 RAG(检索增强生成)的人面临一个尴尬:要么自己手搓 FAISS + 一堆胶水代码,要么去开通 Pinecone 这类付费云服务。没有一个「装上就能用、能直接塞进 Python 脚本、还顺手帮你把原文也存了」的轻量工具。Chroma 的目标就是把向量检索做到像用字典/列表一样简单——它的口号是「the AI-native open-source embedding database」,让开发者用最少几行代码就能完成「存文档 → 自动算向量 → 语义搜索」整个闭环。

用什么语言写的:最初主要用 Python 实现。2025 年完成了一次核心引擎用 Rust 重写的大升级(对应 1.0 版本),写入和查询速度提升约 4 倍,并摆脱了 Python GIL 的多线程瓶颈。对外提供 Python、JavaScript/TypeScript、Rust 等多语言客户端。

开源协议:Apache 2.0,商业友好,可免费自托管。公司靠托管云服务 Chroma Cloud 变现。

用大白话讲三层:

1) 存储层(Storage):Chroma 把数据落到本地一个目录里。其中原文、元数据、ID、全文搜索索引都存在一个 SQLite 数据库文件里(用 SQLite 的 FTS5 做全文检索);向量本身和它的近邻图索引则按「每个集合一个 UUID 子目录」存成几个二进制文件(header.bin / length.bin / link_lists.bin 等)。

2) 索引层(Index)——底层 ANN:单机版用的是 HNSW(分层可导航小世界图)。可以把它想成一张「朋友找朋友」的关系网:相似的向量互相连成邻居,查询时从图上某点出发,顺着边一路跳向越来越近的点,于是不用和全部数据逐个比对,达到接近对数级的查询速度。每个集合维护一份自己的 HNSW 索引,默认主要驻留在内存里以保证速度。分布式/云端则换用 Chroma 自研的 SPANN 索引(分区树 + 图的组合),专为「单机内存装不下的超大数据集」设计。

3) 查询怎么走:你发一个查询 → 若没给向量,先用 embedding 函数把查询文本算成向量 → 拿这个向量去 HNSW 图里找最近的 K 个邻居 → 同时按 where(元数据条件)和 where_document(全文/正则)在 SQLite 里做过滤 → 把向量距离 + 过滤结果合并 → 返回带原文、元数据、相似度距离的结果列表。

部署形态:① 内嵌(in-process)——直接 import 进你的程序,零额外进程,数据存本地目录;② 单机 Server——chroma run 起一个 HTTP 服务,多个客户端连它;③ Chroma Cloud——官方 Serverless 托管,跑在 AWS/GCP 多区域,用同一套 API,只是后端换成可横向扩展的分布式索引。

③ 存入的数据长什么样(真实代码白盒)

# 安装:pip install chromadb —— 一行装好,无需起任何服务 import chromadb # ① 建客户端。PersistentClient 会把数据落到本地目录(可不传=纯内存) client = chromadb.PersistentClient(path="./chroma_data") # ② 建集合(collection ≈ 一张表)。不指定 embedding 函数时, # Chroma 默认用内置的 all-MiniLM-L6-v2 自动把文本转成向量 collection = client.create_collection(name="my_docs") # ③ 插入数据:重点 —— 同时存 原文 documents + 向量 embeddings + 元数据 metadatas # 这里不传 embeddings,让 Chroma 拿 documents 自动算向量(上手极简) collection.add( ids=["d1", "d2", "d3"], documents=[ "猫是一种常见的家养宠物。", "狗对人类非常忠诚。", "Python 是一门流行的编程语言。", ], metadatas=[ {"topic": "animal", "year": 2023}, {"topic": "animal", "year": 2024}, {"topic": "tech", "year": 2024}, ], ) # 注:索引(HNSW)在 add 时自动增量构建,无需手动"建索引"这一步 # ④ 进阶:也可以自己传向量(用别的模型算好的),长度需与集合一致 collection.add( ids=["d4"], embeddings=[[0.12, -0.03, 0.88, 0.45]], # 你的自定义向量 documents=["老虎属于猫科动物。"], metadatas=[{"topic": "animal", "year": 2024}], ) # ⑤ 查询:用文本直接查(Chroma 自动把查询也转成向量),并按元数据过滤 results = collection.query( query_texts=["哪种动物最忠诚?"], # 或用 query_embeddings=[[...]] 直接传向量 n_results=5, where={"topic": "animal"}, # 元数据过滤:只在动物类里找 where_document={"$contains": "忠诚"}, # 全文过滤:原文需含"忠诚" ) # 返回里同时带 ids / documents(原文)/ metadatas / distances(距离) print(results["documents"]) print(results["distances"])

它在磁盘上大概怎么落地:上面 path="./chroma_data" 会生成一个目录,里面有一个 SQLite 文件(chroma.sqlite3,存所有 ID、原文 documents、metadatas 和全文 FTS 索引),外加每个集合一个以 UUID 命名的子目录(里面是 HNSW 向量索引的二进制文件)。纯内存模式则什么都不落盘,进程退出即清空——所以原型用内存、要持久化就用 PersistentClient 或开 Server。

④ 优势 / 劣势

✓ 优势

  • 上手极简,几乎零配置:pip install chromadb 后几行代码就能跑通「存→查」,新手友好度在向量库里数一数二。
  • 自动 embedding:可以只传文本、不传向量,Chroma 内置模型帮你算,省去对接 embedding 模型的麻烦。
  • 原文 + 向量 + 元数据一站式存:查询结果直接带回原文,做 RAG 时不用再去别的数据库捞原始内容。
  • 内嵌即用、无需运维:能直接 in-process 跑在你的程序里,不必单独起服务、配集群,本地开发体验顺滑。
  • 检索能力齐全:支持元数据过滤、全文/正则过滤(where_document),并向混合检索(2025 起加稀疏向量)演进。
  • 有平滑的上云路径:本地写好的代码几乎原样能切到 Chroma Cloud(同一套 API),从原型到生产过渡平滑。

✗ 劣势

  • 单机规模有上限:开源单机版的舒适区约百万级(常见说法 ~1–10M 向量),数据再大性能会明显下降,需要靠 Cloud/分布式。
  • HNSW 索引吃内存:向量索引默认偏向驻留内存,向量多、维度高时内存占用会成为瓶颈。
  • 分布式/超大规模能力较新:真正横向扩展主要靠 Chroma Cloud(2025-08 才 GA),自建大规模分布式集群的成熟度不如老牌方案。
  • 不是通用数据库:它专注向量+元数据检索,不适合当事务型主库或做复杂 SQL 关联查询。
  • 历史接口有变动:从 0.x 到 1.0(Rust 重写)经历过 API 与默认行为调整,跟着旧教程可能踩到版本差异。
  • 高并发/企业级特性偏轻:相比 Milvus/Qdrant,在精细化分片、配额、企业治理等重型能力上更精简。

⑤ 什么时候选 / 什么时候别选

✓ 适合

  • 做 RAG / 语义搜索原型,想要最快从 0 到 1 跑起来。
  • 个人项目、Demo、教学,不想为了一个向量库去运维一整套服务。
  • 数据量在几万到几百万级、单机/单实例就够用的中小场景。
  • 希望原文和向量一起存、查出来直接喂给大模型,少写胶水代码。
  • 已用 LangChain / LlamaIndex 等框架,想要一个开箱即用、生态默认支持的向量后端。

✗ 别用

  • 要存上亿级向量、需要重度横向扩展且坚持完全自建集群时,Milvus 等更稳。
  • 对极致 QPS / 超低延迟 / 复杂分片有硬性 SLA 的大型生产系统。
  • 想把向量检索直接长在现有关系库里(那就用 pgvector,省一套系统)。
  • 需要企业级多租户、细粒度权限、合规治理等重型平台能力。
  • 把它当通用主数据库用(它不为事务/复杂 JOIN 设计)。
一句话:Chroma 是「最容易上手」的开源向量数据库——一行 pip 装好、能内嵌进 Python 程序、把原文/向量/元数据一站式存好,底层用 SQLite + HNSW;它是把 RAG 原型快速跑起来的首选,中小规模够用,真要上亿级或极致性能再考虑迁到 Chroma Cloud 或换 Milvus/Qdrant。
