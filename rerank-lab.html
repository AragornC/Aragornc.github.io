重排白盒 · Cross-Encoder 精排(真模型)

第 ⑧ 步:召回粗筛出候选后,用交叉编码器对「查询+每篇候选」逐对精打分,重新排序。← 混合检索 · 导航

🎯 这页用的是真的中文 reranker 模型(bge-reranker-base,本地加载),不是模拟。它和召回用的 bge 是两种不同的模型——区别就在下面这张图,先看懂它,再看排名怎么变。

召回用的:Bi-Encoder(双塔/bi=双)

query 和 doc 各自单独编码成一个向量,最后只比 cosine。doc 的向量能提前算好存库里 → 查询时极快。但 query 和 doc 从头到尾没"见过面",只在最后比了下方向 → 粗。
query →[模型]→ 向量Q ┐ doc →[模型]→ 向量D ┘→ cosine(Q,D) （两边分开算，doc可预存）

重排用的:Cross-Encoder(交叉/cross=交叉)

把 query 和 doc 拼成一句话一起喂进模型,模型内部让两者逐词互相"对照",直接吐一个相关性分。准得多。但没法预存(每个 query 都得和每篇 doc 现拼现算)→ 慢 → 只能用在召回后那一小撮候选上。
[query ＋ doc] →[同一个模型]→ 相关分 （拼一起进去，query和doc逐词交互）
点按钮:加载召回模型 + 重排模型(重排模型 ~280MB,首次稍久)。
漏斗:全库 → 召回(bi-encoder)粗筛 top-N → 重排(cross-encoder)精排 → 取最终 top-k 喂 LLM。下面左=召回排名,右=重排后排名,中间箭头=名次变化。

① 召回排名(bi-encoder cosine)

快、粗。topical 相似就排前,不一定真回答了问题。

② 重排后(cross-encoder 精排)

慢、准。读懂"查询↔候选"的真实关系后重排。橙底=最终 top-k。
为什么不一开始就用 cross-encoder 搜全库?因为它必须 query+doc 现拼现算,没法预存向量。全库几百万篇,每次查询都现算几百万次 → 慢到不可用。所以分两步:召回(快)负责"别漏",重排(准)负责"排对",只对召回出的那几十条候选跑重排。这就是"粗召回保全、重排保准"。
