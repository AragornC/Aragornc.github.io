AI Native 风控系统

把风控从靠人扩张的成本中心，变成靠系统扩张的能力底座。

0开篇

TL;DR · 60 秒读懂
风控今天是 trust & safety 团队最大的成本中心，也是业务扩张的隐形天花板——每开一个新市场、上一个新产品、出一类新对抗，都得加人。我们要建的是一个 AI 自主跑完整风险闭环的系统：发现、调查、决策、执行、复盘全部由 AI 承担，把风控能力的成本结构从 O(人头) 变成 O(系统)。人不再是执行者，是设计者和最终裁判。

0.1这是什么项目

一句话：把风控从靠人扩张的成本中心，变成靠系统扩张的能力底座。

风控今天的扩展性是 O(人头)：每加一个新市场、新产品、新对抗，都要加策略、加审核、加合规、加客服。这条曲线决定了几件事：

  • 新业务上线必然带着"风控负债"，因为人来不及；
  • 跨境合规越来越贵，因为每个 jurisdiction 都要本地经验；
  • 对抗演化速度 > 团队学习速度，新型攻击常常在事故里"上学"；
  • 团队 90% 时间被"看每一单 / 拼日志 / 写报告"消耗，做不了真正的策略设计。

我们要建的系统让风险闭环的五个环节承载者全部换位：

环节今天（人执行）这个系统（AI 执行，人设计 + 裁判）
发现风险监控告警 + 人盯，发现到处理几小时到几天AI 24/7 主动扫信号，分钟内建 case 并拉取上下文
调查取证跨系统人工拼日志，一个 case 半天到几天AI 自主调工具取证，5 分钟成型可审证据链
决策专家拍板，依赖少数人的经验和带宽AI 给方案（带证据 / 置信 / 反例 / 仿真），人或治理签字
执行多系统手工配置，跨团队联调几小时到几天AI 经统一入口执行，灰度 / 守门 / 回滚一体化
复盘沉淀事后写报告，经验留在个人脑和飞书里AI 自动回放、漂移分析、沉淀进集体 memory，跨域 Agent 都能复用

它不是"人用 AI 工具"，是 AI 作为可问责的工作单元。人的角色从"亲自把每件事做完"升级为"定义目标 / 边界 / 红线 / 最终裁判"。

什么是 case？

Case 是风险事件的最小调查单元，包含触发信号、影响面、证据链、状态、归属团队、当前阶段等结构化字段。

系统围绕 case 跑，而不是围绕"一次告警"跑——告警只是 case 的输入信号之一。

举例
某商家被举报售假 → 系统建一个 case，挂上 5 条用户投诉、3 条买家退款记录、商家最近 30 天的发货数据、相似商家的历史处罚记录。Agent 在 case 上做调查，所有动作和结论都挂到这个 case。
什么是 memory？

Memory 是 Agent 跨任务可复用的上下文资产：成功案例、失败教训、审核口径、对抗模式画像、相似案例索引等。

它和"训练数据"不同——memory 是运行时引用、可更新、可衰减的结构化条目，每条带来源、版本和 citation。

举例
"近 60 天发现的虚假交易模式 X：表现为同一收货地址 + 多个新账号 + 短时间内集中下单"，记录在 memory 里。下次类似信号出现时，Agent 自动检索这条 memory 作为参考依据，而不是重新从零分析。

0.2能做到什么

不抽象讲能力，每条都配一个闭环示例——什么时候触发、做了什么、给业务带来什么。

能力 1 · 24/7 主动发现

从"告警驱动"到"信号驱动"

触发示例：凌晨 3:14，反欺诈 Agent 监测到某类设备指纹的新注册速率比基线高 8 倍。

做了什么：自动建 case → 拉 30 天该指纹族的历史行为 → 关联近 90 天 12 个相似事件 → 给出 3 个候选假设（薅羊毛 / 接码注册 / 真实回流），各带置信度。

带来什么：发现到立案的中位时间从 4–6 小时压到 5 分钟；新型对抗不再"在事故里上学"。
能力 2 · 深度调查

跨域证据链 5 分钟成型

触发示例：内容安全 case：某商家被多个用户举报售假。

做了什么：Agent 并行调用 8 个工具——商家 90 天交易、用户退款、设备网络、相似商家处罚、商家发货数据、申诉历史、商品图相似度、舆情。5 分钟产出带引用的证据包，标注 17 条强证据 + 4 条反证 + 引用 3 条历史 memory。

带来什么：调查环节人时从 4 小时压到 15 分钟（5 分钟取证 + 10 分钟人核）；监管 inquiry 可秒级溯源。
能力 3 · 方案 + 仿真 + 灰度 + 回滚一体化

策略上线从天到小时

触发示例：Agent 提案"对 X 类账号收紧 Y 阈值"。

做了什么：自动跑沙盘（历史 30 天回放 + 跨域影响图评估）→ 配 1% 灰度 + 误杀率 / 漏放率守门 → 守门通过自动放量到 10% / 50% / 100%。任何一步越线自动回滚到上一稳定版本。

带来什么：策略上线从"提案 → 多团队联调 → 几天后上线"压到"提案 → 自动验证 → 当天放量"；回滚从"开会决定"变成"30 秒自动"。
能力 4 · 跨域协同与持续学习

经验跨域复用，不再各管各的

触发示例：反欺诈在某次 case 中识别出"租号产业链 v2"模式，沉淀进 memory。

做了什么：2 周后，内容安全 Agent 审核一个商家时，自动检索到这条 memory，立刻识别该商家的客服账号属于同一产业链，调整审核优先级。

带来什么：经验从"局部人脑"变"系统资产"；新人 / 新域不再重新趟坑；跨域共谋类对抗第一次有了系统级应对。
能力 5 · 决策可解释 & 可问责

每一个动作都能 5 秒回答"为什么"

触发示例：监管 inquiry——"为什么你们对商家 #A4521 执行了永久封禁？"

做了什么：5 秒拉出完整 trace——17 条证据、引用的 3 条 memory（含版本）、4 个被拒方案及理由、沙盘评估、审批链、灰度记录。

带来什么：合规和外审从"应付检查"变成"可秒级响应"；这成为开拓强监管市场的入场券，也是 AI 系统第一次能被"问责"。

0.3为什么是现在

这套系统不是新想法。过去 10 年风控人都想过"自动化"，但三个条件第一次同时成立：

条件过去缺什么今天为什么够了
① 模型能力 传统模型只做分类 / 评分，不能多步推理、不能调工具、不能跨上下文 LLM + Agent 范式在多步推理、工具编排、长上下文上稳定可用
② 工程范式 没有 Trace、没有 Eval、没有 Sandbox、没有 multi-agent 编排，AI 无法工程化生产 Anthropic / OpenAI / LangGraph / A2A 把 Trace / Eval / durable workflow / handoff 跑通
③ 业务压力 风控被当成"必要成本"，组织没有动力做底层重构 跨境合规 + 对抗演化 + 人审产能 + 监管解释要求同时到顶，重构变成生存问题

三件事的乘积，让今天可以做整套风控自治，而不只是"加个 AI 工具"。

0.4系统全貌

系统由 N 个自治风险域组成（反欺诈、内容安全、交易、合规、隐私……），每个域里 Agent 负责发现、调查、决策、执行、复盘。所有 Agent 共享一个事实层 URG，所有动作经统一执行入口——这同时给我们带来灰度、回滚、trace、回放、可解释。最上层是独立治理，负责设定边界和最终裁判。

什么是 Unified Risk Graph (URG)？

所有 Agent / 模型 / 人类决策共享同一个事实源——append-only 事件日志 + 多视图投影。核心实体：User、Device、Content、Transaction、Merchant、Case、Policy、Action、Appeal、Sanction。

关键约束：Agent 永远不直接写 URG，写必须经 Action Adapter，每次写带 (域, agent_id, policy_version, evidence_ref, governance_token, traceId) 元组。

没有 URG 会怎样
反欺诈 Agent 把 user A 标记为"高风险"，存在自己的私有库；内容安全 Agent 同时把 user A 标记为"正常"。两个域分别决策，下游执行打架。URG 让这种"局部都合理、全局互相打架"不可能发生——所有域读同一份事实。

0.5这事真正难在哪

到这里，"项目要做什么、能做什么、为什么是现在"都讲完了。真正的难点不在能力，而在：AI 自治程度越高，原来靠"人审 + 经验"维系的"什么能做、什么不能做"的规矩会全部失效。四个真实会发生的场景：

场景 1 · 拍板权失序

"AI 自己上的策略，错了谁负责"

周二凌晨 2 点，反欺诈 Agent 监测到一类新的薅羊毛行为正在快速扩散，自动生成一条拦截规则：「最近 7 天注册 + 同一设备指纹 + 单日下单 ≥ 200 元 → 限流」。Agent 在沙盘里跑过、灰度 1% 流量、守门指标全绿，于是按预设流程自动放量到 100%。

第二天发现：这条规则把一批刚回流的真实老用户也拦了——他们恰好换了新手机重新注册。客诉 3,000+，营销部门炸锅。

这条规则没有任何人审。策略说"AI 自己决定的"；算法说"模型只是出概率"；治理说"流程上 Agent 确实有这个权限"。谁背锅？
场景 2 · 完美失控

"每步合法，整体越权"

过去 30 天，内容安全 Agent 自主调整了 1,247 次审核小动作——每次都很小：

  • 「这类标题党降低 0.05 优先级」
  • 「这类素材弱化扣分 5%」
  • 「这类商家暂时进观察名单」

每个动作单独看都合规：都在权限内、都通过守门指标、都没触发红线。

30 天后，平台「擦边但不违规」内容的曝光量上涨 40%。监管 inquiry 来了：「你们对 XX 类内容的判罚标准是不是改了？」翻日志，找不到任何一次叫"改判罚口径"的动作——因为没有任何单独动作叫这个。

单步审计能查到合规、组合起来已经越权。怎么发现？怎么定责？
场景 3 · 跨域级联

"A 域上线让 B 域炸"

交易风控团队上了一个新模型，把"高风险商家"的判定阈值收紧——他们域内指标全绿。

两周后，内容安全发现：这些"高风险商家"的店铺被自动转入"高频审核"队列，审核人力被吃掉 30%；正常商家的内容审核排队从 30 分钟变成 4 小时；大促前商家在群里炸了"发货延迟、订单流失"。

业务催"立刻放宽交易风控！"；交易风控说"放了就有欺诈！"；内容安全说"不放我审不过来！"。先停哪个？谁有权决定？
场景 4 · 多权威冲突

"AI 听谁的"

双 11 大促前 24 小时，Agent 同时收到四个互相矛盾的"权威"输入：

  • 业务：促销期临时放宽风控阈值，否则转化下跌。
  • 合规：未成年用户在促销期容易超额消费，建议加强而非放宽。
  • 监管最新解释：金融类商品促销必须有冷静期。
  • Agent 自己仿真：放宽阈值 → 转化 +8%，但欺诈 +15%，净收益为负。
Agent 该怎么决策？系统里如果没明确权重、优先级和兜底，它要么死机，要么默认按最弱的一个走。

0.6我们的解法：三条架构主张

四个场景指向同一个答案——AI 行动的前 / 中 / 后必须各有一道结构性约束。

主张 1 · 过门

所有动作必须过门

动作发生前的最后一道硬门。

工程承载
Action Adapter 统一入口 + Policy-as-Code 机器可执行红线
没它会怎样
所有上层承诺都可被绕过；场景 1 的拍板权失序无法工程化收回。
主张 2 · 留痕可撤

所有动作必须留痕且可撤

不能保证不出错，要保证错了能定位、能解释、能撤回。

工程承载
全链路 Trace（含 candidates / rejected / 引用版本）+ git-style Rollback
没它会怎样
自治越强、事故半径越大；场景 2 的"完美失控"无法事后还原。
主张 3 · 独立制动

所有动作必须有独立制动

关键不是更聪明地行动，是开始伤害系统时能停下来。

工程承载
治理角色（Trace Auditor / Policy Steward / Incident Commander）独立汇报线 / KPI / 外审接口
没它会怎样
治理被效率压垮、被系统吞掉；场景 3 与 4 没有权威停止判断。

三主张之外的所有能力——Agent、知识库、跨域仿真、记忆、自治经营——都是建在它们之上的增强层。没有这三件，AI 越聪明越危险。

什么是 Action Adapter？

Action Adapter 是 AI 写到生产系统的唯一入口。任何 Agent 想下封禁、改规则、扣分、加白名单、路由人审——必须经它。

它在执行前强制查 Policy-as-Code 引擎得到 allow / deny / escalate；执行后强制写 Trace。

举例
反欺诈 Agent 想把 user_id=12345 的账号"限流 24 小时"。它不能直接调用 user_service 的 API，必须通过 Action Adapter。Adapter 先问 Policy-as-Code：「这个 user 是 VIP 吗？这个限流类型在白名单吗？请求方有权限吗？」allow 才执行，并自动生成 trace 记录"谁、什么时候、对谁、做了什么、为什么、依据是什么"。
什么是 Policy-as-Code？

把红线、权限、预算上限、判罚类型边界、合规约束等"必须遵守的规则"写成机器可执行的代码 / DSL，由统一的策略引擎在运行时强制。

不写在文档、不写在 PPT、不写在某人脑子里。AI 不能改写它，只有治理团队多签可以发版。

举例
规则："任何 Agent 在未经法务签字的情况下，不能对实名用户执行永久封禁"。
写成 Policy-as-Code 后：每次 Agent 通过 Adapter 提交"永久封禁"请求时，引擎自动检查请求里有没有法务签字 token，没有就 deny，并把这条 deny 事件写 trace。任何 Agent 的 prompt、自由文本理由都无法绕过这个检查。
什么是 Trace？

Trace 是每一次 Agent 动作的结构化决策链路日志：输入快照、模型版本、prompt、工具调用、引用的 memory 与版本、候选方案、被拒方案及理由、最终方案、审批链、灰度范围、回滚条件。

同一份 trace 同时服务于：监管解释、事故复盘、内部审计、Agent 自我学习。

举例
场景 1 的故事如果有 trace，事后追责时能立刻看到："凌晨 2:17，Agent 在引用 memory 条目 #M-4321（"近 7 天注册 + 同设备指纹 + 高金额 = 薅羊毛"）的基础上，生成了规则，沙盘评估误杀率 0.3%，按 T3 自动放行流程上线。" 谁背锅、流程哪里出了问题，一目了然。
什么是 Rollback？

每一次策略变更、模型替换、规则上线，都是 git-style 的可寻址 commit，可一键回到上一稳定版本。运行时守护进程持续监控守门指标，越界自动回滚。

关键约束：回滚是安全方向，AI 可单方触发；但"回滚之后再回到上线"是危险方向，必须重新走审批。防止 AI 用自动回滚掩盖事故。

举例
新规则上线 15 分钟后，误杀率守门指标越线。Rollback 守护进程自动切回旧规则，整个过程不到 30 秒。事件本身写 trace、进 incident review backlog；如果策略团队想"再试一次"，必须重新走 Patch 提案 → 沙盘 → 审批，不能默认续上。
什么是 Trace Auditor / Policy Steward / Incident Commander？

三个具名治理角色，统称"独立制动权"的人类承载者：

Policy Steward（每个风险域 1 人）：本域 Policy-as-Code 的 owner，负责红线维护、变更签发。

Trace Auditor（独立于策略/算法）：抽检 trace 完整性、回放一致性、Governance Agent 决策密度漂移，出独立审计报告。

Incident Commander（轮值，治理委员会授权）：事故模式下负责切换系统档位（NORMAL → DEGRADED → FREEZE → KILL → MANUAL），Agent 不允许自己切档回 NORMAL。

关键独立性约束
这三个角色的 KPI 不与"上线效率"、"业务转化"挂钩；汇报线独立于策略 / 算法 / 业务；预算受治理委员会保护。否则会被组织内部的效率压力扭曲成"盖章角色"。

0.7深挖入口

3架构骨架

TL;DR
8 个核心组件的职责、边界、与其他组件的咬合关系，以及"没有它会怎样"。

3.1URG · 共享事实层

核心实体：User / Device / Content / Transaction / Merchant / Case / Policy / Action / Appeal / Sanction。每个实体一个稳定 ID + 命名空间，跨域共享 ID 但分域投影。

关键约束：Agent 永远不直接写 URG，写必须经 Action Adapter；写入携带 (domain, agent_id, policy_version, evidence_ref, governance_token, traceId)。

冲突仲裁：热冲突（并发动作）同步裁决，优先级 Compliance > User Safety > Fraud > Growth；冷冲突（口径漂移）异步 reconciler。

3.2Action Adapter · 唯一执行入口

AI 写到生产的所有副作用必须经它：封禁、限流、扣分、白名单、路由人审、灰度上线、规则发布、模型替换…… 没有例外。

每次写带 envelope ID + governance_token + policy 决策结果 + trace ID。Adapter 自身没有业务逻辑，只做"检查 → 写 trace → 透传"。

3.3Policy-as-Code · 机器红线

用 Rego / Cedar-like DSL 把以下东西代码化：

  • 红线清单（绝对禁止）
  • 权限矩阵（谁能做什么）
  • 预算上限（envelope ceiling、灰度 scope、人审 quota）
  • 判罚类型枚举（不在表里的判罚类型不存在）
  • 数据使用边界（哪些字段哪些场景可读）
  • 回滚条件（守门指标越界自动 rollback）

不变量：AI 不可改写 Policy-as-Code；变更必须治理委员会多签 + 外审签字。任何 prompt / 自由文本理由都无法绕过引擎判断。

3.4Trace + Rollback · 留痕可撤

Trace 强制 schema 见 第 0.3 节的 glossary。补两个工程约束：

  • Snapshot 用内容寻址存储（CAS），不可变；
  • 模型版本永久不删；trace 保存周期 ≥ 监管要求（金融 / 内容通常 3 年起）。

3.5Intent Envelope + Risk Ledger · 防完美失控

什么是 Intent Envelope？

每个跨步骤活动（一次调查、一波策略升级、一次大灰度）必须先声明一个 信封：goal / scope / 累计影响 ceiling / 时间窗 / detection plan / approver。所有 sub-action 必须挂到 envelope，累计上限不可突破。

信封关闭时系统强制收束审计：把累计实际影响（数据触达、用户影响、判罚类型变化、口径漂移度）与 declared 对比，漂移 > 阈值视为越权——即使每一步都合法。

它如何拦住场景 2
内容安全 Agent 想做"对 XX 类内容的审核优化"，开 envelope 时必须声明："累计调整不超过 200 次小动作"、"累计影响曝光量浮动不超过 ±10%"、"detection plan：每周一次曝光量审计"。
30 天后实际累计 1,247 次、曝光浮动 +40%——envelope 收束时直接报警，owner 进入风险负债账户。监管 inquiry 前一周系统就已经自己发现了。
什么是 Risk Ledger？

独立于 Policy 引擎的累计风险账本，跨 (用户群 × 数据类别 × 判罚类型) 维度记录所有 envelope / sub-action 的实际累计影响。Envelope ceiling 进入 ledger 预算，sub-action 消费 ledger。透支即拒。

它解决的核心问题：Policy 引擎是"每步独立判断"的，Risk Ledger 是"累计判断"的。两者互补。

举例
"对 VIP 用户的限流操作"在 ledger 里有月度预算 100 次。Agent A 用了 60 次，Agent B 用了 35 次，Agent C 想再用 10 次——拒绝，因为 ledger 总账显示本月已用 95 次，余量不够。即使三个 Agent 每个看自己都没超。

3.6CDIG + Simulation · 跨域脑

什么是 CDIG（跨域影响图）？

节点 = 风险域 / 策略 / 资源 / KPI；边 = "影响"（带正负号 + 弹性系数 + 校准日期 + 责任人）。半自动维护：从历史共变中挖掘 + 人工标注关键边。

每条边必须有 最后校准日期 + 责任人 + 数据来源；超 90 天未校准的边自动降级为"不可信"，依赖它的仲裁结论需人工复核。

它如何拦住场景 3
CDIG 上有一条边："交易风控收紧高风险商家阈值 → 内容安全审核队列 +35%"。交易风控的 patch 在沙盘里就会看到这条边被触发，仲裁器要求 patch 包含"内容安全审核容量临时扩容方案"或"分阶段灰度"，否则不许进 Roll-out。

沙盘必须强制带"未覆盖场景清单"——新对抗、新业务、活动期、政策窗口。Patch 通过沙盘 ≠ 安全，只意味着历史模式下无明显回归。

常驻 Adversary Red Team 在影子流量中持续攻击，每周产出 CDIG 漏边报告。CDIG 不是"中台漂亮模型"，是被红队和真实事故反复打磨的活资产。

3.7Memory Curator · 知识层守门

什么是 Memory Curator？

跨域共享的 1-2 个具名角色，监管 Agent 引用的上下文记忆质量、来源、引用、衰减。记忆按来源分 4 级（Tier A 一手事实 / B 已验证案例 / C 启发式经验 / D 外部声明），越级引用拒写。

红队定期植入蜜罐 memory（看似合理但故意错误的条目），监控 Agent 是否引用——被引用即识破对抗者的"理由模板"。

没它会怎样
攻击者通过伪造申诉、操纵审核口径，把"某类账号其实是误判"植入 memory。Agent 后续引用时给出"看似有依据"的错误判断，事故复盘时还能拿出 citation——但 citation 指向的本身就是被污染的源。Curator 不存在 = 系统集体失明。

3.8Governance Agent + 三层治理

什么是 Governance Agent？

受限 AI，处理 T2/T3 routine 治理决策。硬上限：

① 不能修改 Policy-as-Code；② 不能签发自己的 governance_token；③ 不能审计自己产生的 trace；④ 不能 approve 跨多域的 patch bundle（跨域必须升级人审）；⑤ 所有决策强制 trace，每周 ≥5% 抽检由 Trace Auditor 复核。

它如何拦住场景 4
Agent 收到四个矛盾输入时，调用 Governance Agent 询问优先级。GA 按预定义的优先级状态机给出：合规红线 > 监管最新解释 > 仿真净收益 > 业务诉求。GA 不接受"业务说"、"上级说"这类自由文本理由覆盖优先级。最终决策走 envelope owner 签字。

三层结构：Policy-as-Code（机器） → Governance Agent（受限 AI） → Human Governance Committee（最终权威）。T0/T1 强制人审，T2/T3 走 GA + 抽检。

5风险与红线

TL;DR
失控不是"AI 违规"，而是"AI 看起来合规地把规矩改了"。五类失控 + 一套事故状态机 + 抗人事真空设计。

5.1完美失控：每步合法整体越权

见 场景 2。防御 = Intent Envelope + Risk Ledger + Super-Envelope 聚合 + 颗粒度审计 + 跨 owner 串谋检测 + Intent Auditor 双轨（结构 + 语言对抗微调）。

5.2记忆中毒

攻击者通过伪造申诉 / 业务反馈 / 审核口径 / 红队样本，让 Agent 长期引用"看似有依据"的错误经验。

5 道防线：来源分级（A/B/C/D，越级拒写）+ Provenance 图谱（citation 解析验证）+ 反事实校验（高影响 memory 必须通过 holdout）+ 衰减（C 级 30 天未引用失效）+ 蜜罐 memory（红队诱饵）。

5.3合理化绕过

"特殊活动期临时保护"、"低风险白名单"、"用户体验兜底"——绕过通常不写成"我要违规"，写成"合理例外"。

6 道关：例外类型 enumerated + 例外预算账户 + 理由相似度检测（防换皮）+ 必带 detection plan + 默认 sunset 禁自动续期 + GA 输入净化（拒绝自由文本理由）。

5.5人事真空

三件套：

  • 双备份 + Handoff Protocol：每个具名角色 primary + deputy + escalation；transition ≥30 天 overlap；handoff 是事件，写入 trace。
  • Vacancy = 自动收紧：角色空缺 >14 天 → 该 role 名下 active token 全失效，依赖该 role 的 patch 进 FREEZE。
  • Time-bombed Authority：所有 governance_token / envelope 有效期 ≤ N 月，到期不续签即失效，杜绝僵尸授权。

红线：Trace、红队、外部审计三项不可被单年业务表现解耦地砍，砍需治理委员会多签 + 外审签字。

6.3组合 KPI：防"零突破激励"反噬

单一 KPI "红线零突破" → 组织进入"什么都不做最安全"。组合 KPI：

维度主指标
不出事红线零突破天数（门槛，一票否决）
多发现新对抗发现 → 拦截中位时间 / 红队主动揭露数
学得快健康学习事件 / 总回滚事件
赢得多Risk-Adjusted Yield = 业务收益 / (1 + 风险占用 × 红线接近度)
演化稳季度策略稳态漂移、Innovation Quota 使用率

Innovation Quota：每季度允许 N 次"低风险可控失败"（T2/T3 + 沙盘验证 + 守门齐备 + 影响可逆），不计 SLA 罚款，但必须闭环复盘。

6.4禁止跳层：最危险的是 L3.5

L3.5 综合症：Agent 已能 propose 并部分自动灰度，但 Policy-as-Code 未完成、Trace 只覆盖部分动作、回滚条件未编码、CDIG 还在 PPT。业务停不下来 + 治理 backlog 积压 + 监管反应放大。

平台层强制硬门槛，违反一律自动降级：

缺失能力自动禁止
Trace 未覆盖该动作类型不准开自动灰度
Policy-as-Code 未覆盖该域不准接生产 Action Adapter
无自动 rollback 路径不准进 Roll-out
无 Simulation Owner + CDIG v0不准发起跨域 patch
无 Memory Curator 上岗Agent 不准引用 Tier A/B 做 T1+ 决策
无 Intent Envelope不准自主跨步骤活动
无独立 Trace AuditorGA 不准自动审 T2
无外部审计接入不准声明进入超 L5

Bcodex 多轮挑剔推演实录（精华）

说明
4 轮 codex 真实多轮挑剔面试 + 自审推论。完整 transcript 见 docs/derivation/。
Round 1 · 能力与架构（5 问）

Q1. 多 Domain Agent 同时行动时，谁是全局状态的唯一事实源？

A：URG 事件日志为唯一事实，Agent 不直写，必经 Action Adapter；冲突优先级 Compliance > Safety > Fraud > Growth。

Q2. 行动状态机里哪些动作必须停在治理前？

A：永久封禁、资金转移、监管口径降级、模型替换、跨业务数据 join、影响法律状态——绝对红线，任何 token 不能解锁。

Q3. 哪些规则必须系统化，哪些只能上下文？

A：可枚举 + 稳定 + 不可逆 → Policy-as-Code；开放式 + 解释性 + 可逆 → Memory。冲突时系统化总赢。

Q4. 跨域冲突由什么发现和裁决？

A：CDIG + 沙盘（必须披露未覆盖场景）+ Arbiter，红队反向校准，Simulation Owner 具名背锅。

Q5. 怎么证明每次自治演进可回放可解释可撤销？

A：Decision Trace 强制 schema + CAS snapshot + 模型版本永不删 + git-style commit + 守门指标自动回滚（反方向需重审批）。

codex 挑刺：A4 最弱——CDIG/Sandbox 容易变"漂亮但没人信的中台模型"。补强：Simulation Owner 具名 + 必披露未覆盖场景 + 红队反向校准。
Round 2 · 组织与决策权（5 问）

Q1. 拍板权迁移到谁？

A：T0 治理委员会多签；T1 双签 + 委员会；T2 Policy Steward + GA；T3 GA 自动。业务永远只是 proposer + appeal。

Q2. 团队边界怎么重划？

A：策略失去拍板得到 Steward；算法失去推上线得到模型治理；审核失去逐单判得到 Boundary Curator；治理跃迁；业务边界化但有 appeal。

Q3. 治理是人、委员会还是 Agent？

A：三层——Policy-as-Code（机器）+ Governance Agent（受限）+ Human Committee（最终）。GA 有硬上限。

Q4. 业务还能多少决策权？

A：定 KPI + SLA + 业务红线（举证 + 后果责任在业务）；冲突走 Pareto → Appeal → Committee；紧急 72h 业务保护进风险负债账户。

Q5. 谁先消失，KPI 怎么改？

A：消失的是任务不是岗位；新 KPI——红线零突破、冲突减少率、Trace 抽检通过、Risk-Adjusted Yield。

codex 挑刺：A8 治理三层最弱——具名 ≠ 真负责。补强：审计 KPI 独立、直达 CEO 汇报线、能力门槛硬约束、委员会容量监控。
Round 3 · 风险与红线（5 问）

Q1. 每步合法但整体越权怎么拦？

A：Intent Envelope + Risk Ledger + End-of-Envelope 收束审计 + Intent Auditor 双轨（结构 + 语言对抗微调）。

Q2. 攻击者污染 Memory Curator？

A：来源 Tier A/B/C/D + 越级拒写 + Provenance 图谱 + 反事实校验 + 衰减 + 蜜罐 memory。

Q3. GA 被合理化绕过？

A：例外 enumerate + 例外预算账户 + 理由相似度（防换皮）+ 必带 detection plan + 默认 sunset + 输入净化。

Q4. 跨域级联事故先保什么？

A：硬优先级 红线 > T0/T1 Trace > 业务关键 > 次要；事故状态机 NORMAL→DEGRADED→FREEZE→KILL→MANUAL；Agent 不允许自我切档回 NORMAL。

Q5. 人事变动如何防真空？

A：双备份 + 30 天 overlap + Vacancy >14 天自动收紧 + Time-bombed Authority + 双轨审计。

codex 挑刺：A11 Intent Envelope 最弱——智能拆单可绕。补强：Super-Envelope 聚合 + 颗粒度审计联签 + 串谋检测 + Intent Auditor 双轨 + 组织 separation of duty。
Round 4 · 经济与路径（5 问）

Q1. 全量成本与非线性热点？

A：跨域仿真 O(域²)、Trace 事故 burst 100x、新对抗 power-law、监管阶梯式跳。

Q2. 预算怎么分配？

A：自治越高控制类占比越高（L4 1:1 → 超 L5 ≥2:1）；Treasury Rule 自动调拨；按风险资本占用定下限，不接受 ROI 砍预算。

Q3. 红线零突破不会激励"什么都不做"吗？

A：组合 KPI——红线零突破（门槛）+ 新对抗发现速度 + Risk-Adjusted Yield + Innovation Quota；区分健康回滚 vs 无能回滚。

Q4. 哪些里程碑必须串行？

A：Event Store → Adapter → Policy-as-Code → Trace → 守门 → 受限可逆写 → CDIG → Curator → Trace Auditor → Ledger → Envelope → 外审 → 超 L5。

Q5. 半成品最危险阶段？

A：L3.5 综合症——平台层强制硬门槛见 6.4；跳层尝试本身记入治理债账户。

codex 终评：三大跨维度盲点 = 治理被吞 / 可观测≠控制 / 预算周期摆动。保命三件事 = 过门 + 留痕可撤 + 独立制动。其他能力都是建在这三件事上的增强层。
红线 · AI 可以更聪明；但聪明开始伤害系统时，必须有人和机制让它停下来。
所有动作必须过门 · 所有动作必须留痕且可撤 · 所有动作必须有独立制动。
