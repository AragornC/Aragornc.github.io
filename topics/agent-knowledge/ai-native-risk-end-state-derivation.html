AI Native Risk · Backward Derivation from End State

以终为始：从「超 L5 稳态」倒推 AI 风控系统

不假设我们在 L? 层，先定义生态级稳态长什么样，再问下面这套系统需要什么能力、组织、红线、经济模型才能撑住——以及现在缺什么。

终态：多风险域协同 + 跨业务 + 生态级。衡量不是单条策略效果，而是抗熵能力。
方法：4 维度（架构 / 组织 / 风险 / 经济）× 5 轮 codex 挑剔面试 × 自我反驳。
骨干：所有动作必须过门 / 必须留痕且可撤 / 必须有独立制动。
红线：AI 可以聪明，但聪明开始伤害系统时，必须有人和机制让它停下来。

三句话骨架：保住超 L5 的最小条件

codex 最后一刀给出的"如果只能保 3 件事"——其他能力都是建在这三件之上的增强层。

PILLAR 1 · 过门

Action Adapter + Policy-as-Code

所有生产副作用必须经统一入口 + 机器可执行红线。
它比 Governance Agent、Memory、CDIG 更基础，因为后者都可能判断错，Adapter 是动作发生前的最后一道硬门。

PILLAR 2 · 留痕且可撤

全链路 Trace + 可回滚

超 L5 不能保证永不犯错，只能保证犯错后可定位、可解释、可撤销、可学习。
Trace 不是为审计报告，而是为责任链、证据链、复盘入口；rollback 把"可控失败"从口号变工程事实。

PILLAR 3 · 独立制动

真实否决权

Trace Auditor / Policy Steward / Incident Commander 不是头衔，而是体现在汇报线、KPI、预算保护、外部审计接口上的真实否决权。
关键不是更聪明地行动，而是聪明行动开始伤害系统时能停下来。

三大跨维度盲点

这不是单条答案的弱点，而是把 4 个维度分别看都没毛病、合起来会塌的结构性问题。

1

治理会被系统吞掉

架构、组织、红线、预算都依赖治理保持独立、清醒、强势。但治理角色本身也在 KPI、预算、汇报线、事故压力里运行。
系统越复杂越需要治理，越追求效率越压缩治理；最终治理被包装成流程自动化，看起来有 token、有 trace、有委员会，实际没有独立制动能力。

2

可观测 ≠ 控制

Trace、Envelope、Risk Ledger、CDIG、Simulation 增强了可见性，但可见性不等于实时控制力。
真实事故里最先失效的是理解速度：信号太多、trace 太长、跨域依赖复杂，人和 Agent 都只能在局部解释里行动。最后不是没有数据，而是数据把责任稀释了。

3

治理预算的周期性摆动

Treasury Rule、风险资本、控制预算下限，都默认组织愿意承认长期风险资本的真实性。
但业务会用确定的增长损失对抗不确定的未来事故；系统在顺风期削薄控制层，事故后报复性加固——形成周期性摆动，而非稳态抗熵。

倒推链路图：从终态向下穿透

每一层的存在必须能回答：「不存在它，终态会怎么坍塌？」

0 · 终态超 L5 稳态
多风险域协同 + 跨业务 + 生态级。衡量不是某条策略效果，而是抗熵能力——面对新型对抗、新业务、新监管、人员流动，系统能否在不破坏红线的前提下持续自我演进。
1 · 全局事实层Unified Risk Graph
  • 事件源（append-only event log）+ 多投影；Agent 永远不直接写，只能经 Action Adapter；
  • 跨域冲突仲裁：热冲突同步裁决（Compliance > Safety > Fraud > Growth），冷冲突进 Disagreement Queue；
  • 不存在它 → 多域协同退化成多个自动化烟囱，"局部都合理，全局互相打架"。
2 · 强制门Action Adapter + Policy-as-Code
  • 所有生产副作用必须经 Adapter；Adapter 必须先查 Policy-as-Code 引擎得 allow/deny/escalate；
  • 红线 = 机器可执行 DSL，AI 不可改写，只能治理团队多签变更；
  • 不存在它 → 所有上层承诺都可被绕过。
3 · 行动状态机Envelope + Trace + Rollback
  • 状态机：Observe → Investigate → Hypothesize → Propose → Simulate → Gray → Roll-out → Monitor → Rollback/Conclude → Memorize；
  • 每个跨步骤活动必须有 Intent Envelope（goal/scope/ceiling/detectionPlan/expiry），所有 sub-action 挂信封；
  • End-of-Envelope 收束审计：累计漂移 > 阈值 = 越权，即使每步合法；
  • 所有动作必发 Trace（含 candidates + rejected + 引用版本），可回放、可撤销；
  • 不存在它 → 自治越强，事故半径越大。
4 · 跨域脑CDIG + Simulation + Arbiter
  • 跨域影响图 CDIG：节点 = 域/策略/资源/KPI，边带弹性系数 + 校准日期 + 责任人；
  • 沙盘强制披露"未覆盖场景清单"，过去无回归 ≠ 未来不会炸；
  • 常驻 Adversary Red Team 持续校准 CDIG，蜜罐 memory；
  • 不存在它 → 跨域级联事故无人能提前看见。
5 · 上下文资产Memory + Knowledge + Curator
  • 记忆来源分级（Tier A 事实 / B 验证 / C 启发 / D 外部声明），越级引用拒写；
  • Provenance 图谱 + citation 解析验证 + 衰减规则 + 双人验证；
  • 红队蜜罐 memory 反向校准；
  • 不存在它 → Agent 引用看似有证据的错误经验，集体失明。
6 · 独立治理三层结构 + 具名角色
  • Policy-as-Code（机器）+ Governance Agent（受限 AI）+ Human Committee（最终权威）三层；
  • 具名角色：Policy Steward / Memory Curator / Trace Auditor / Simulation Owner / Adversary Red Team；
  • Trace Auditor 独立汇报线、独立 KPI、不与上线效率挂钩；
  • 不存在它 → 治理被系统吞掉，自治变失控。
7 · 经济底盘Risk Ledger + Treasury Rule
  • 累计风险账本（用户群 × 数据类别 × 判罚类型）；Envelope 消费 ledger，透支即拒；
  • Treasury Rule：红线突破 / break-glass / Trace lag 自动触发预算从增长侧划拨控制侧；
  • 风险资本占用（EAD × LGD）→ 控制预算下限，不接受短期 ROI 论证砍预算；
  • 不存在它 → 预算周期性摆动，顺风期削控制、事故后补，永远到不了稳态。
8 · 事故模式NORMAL→DEGRADED→FREEZE→KILL→MANUAL
  • 硬优先级：红线 > T0/T1 Trace > 业务关键路径 > 次要路径 > 优化项；
  • 切档由 Incident Commander 触发，Agent 不允许自我切档回 NORMAL；
  • Kill switch 物理冗余、独立鉴权、离线可触发；
  • 不存在它 → 级联事故时，无权威停止判断。
9 · 抗人事真空双备份 + 自动收紧
  • 每个具名角色 = primary + deputy + escalation；transition 必须 ≥30 天 overlap handoff；
  • Vacancy >14 天 → 该 role 名下 active token 全部失效，依赖该 role 的 patch 进 FREEZE；
  • 所有 token / envelope 有效期 ≤ N 月，到期不续签即失效；
  • 知识非人化：CDIG / Policy-as-Code / Memory / Trace 是组织记忆物质载体，离职带不走口径；
  • 不存在它 → 一次组织变动就能掏空整套体系。

四维度核心结论

每个维度的最锋利结论；展开看推演实录可点下方"问答实录"。

维度 1 · 能力与架构

事件为真，写入受限，仲裁兜底

事实源 = URG 事件日志，Agent 私有记忆只是缓存
行动状态机的"过门"是 token + envelope，不是仅 approval
系统化（红线 Policy-as-Code）vs 上下文（memory）冲突时，系统化总赢
跨域不是事后救火，是上线前的强制门禁（CDIG + Sandbox + Arbiter）
Trace 必须能让监管、内部、业务用同一份解释
维度 2 · 组织与决策权

权力迁移到治理，独立性靠汇报线

决策权按 T0/T1/T2/T3 风险分层；业务永远不是 approver，只是 proposer + appeal 发起人
策略失去拍板权、得到 Policy Steward；算法失去推上线、得到模型治理
新具名角色：Policy Steward / Memory Curator / Trace Auditor / Simulation Owner / Adversary Red Team
Governance Agent 有硬上限：不能改红线、不能签自己 token、不能审自己 trace、不能跨域 approve
KPI 从个人产出 → 系统健康：红线零突破天、跨域冲突减少率、Risk-Adjusted Yield
维度 3 · 风险与红线

不只防违规，更要防"合规化失控"

Intent Envelope + Super-Envelope 聚合 + 颗粒度审计，防"智能拆单"越权
记忆中毒五件套：来源分级、Provenance、反事实校验、衰减、蜜罐
例外申请必须 enumerated 类型 + 必带 detection plan + 默认 sunset，禁止自动续期
事故状态机硬优先级：红线 > Trace > 业务关键 > 次要；Agent 不允许自我切档回 NORMAL
Vacancy = 自动收紧，不是沿用旧授权
维度 4 · 经济与路径

自治越高，控制预算占比越高

非线性热点：跨域仿真 O(域²)、Trace 事故 burst 100x、新对抗 power-law
L4 控制:增长 ≥ 1:1；L5 ≥ 1.5:1；超 L5 ≥ 2:1
Trace / 红队 / 外部审计预算不可被单年业务表现解耦地砍，砍需治理委员会 + 外审多签
组合 KPI：红线零突破 + 新对抗发现速度 + Risk-Adjusted Yield + Innovation Quota
最危险阶段：L3.5（Agent 已写、Trace/红线/CDIG 未齐），平台层必须自动降级

codex 多轮挑剔实录（精华）

每轮 codex 作为挑剔面试官提问，自审推论作答；codex 反过来挑刺、推进下一维度。完整 transcript 见 docs/derivation/。

Round 1 · 能力与架构 5 问
Q1. 多 Domain Agent 同时行动时，谁是全局状态的唯一事实源？
A：URG 事件日志为唯一事实，Agent 不直写，必经 Action Adapter；冲突优先级 Compliance > Safety > Fraud > Growth。
Q2. 行动状态机里哪些动作必须停在治理前？
A：永久封禁、资金转移、监管口径降级、模型替换、跨业务数据 join、影响法律状态——绝对红线，任何 token 不能解锁。
Q3. 哪些规则必须系统化，哪些只能上下文？
A：可枚举 + 稳定 + 不可逆 → Policy-as-Code（AI 不可改写）；开放式 + 解释性 + 可逆 → Memory（带 citation）。冲突时系统化总赢。
Q4. 跨域冲突由什么发现和裁决？
A：CDIG + 仿真沙盘（必须披露未覆盖场景）+ Arbiter，红队反向校准，Simulation Owner 具名背锅。
Q5. 怎么证明每次自治演进可回放可解释可撤销？
A：Decision Trace 强制 schema + CAS snapshot + 模型版本永不删 + git-style commit + 守门指标自动回滚（反方向需重审批）。
codex 挑刺：A4 最弱——CDIG/Sandbox 容易变"漂亮但没人信的中台模型"。补强：Simulation Owner 具名 + 必披露未覆盖场景 + 红队反向校准。
Round 2 · 组织与决策权 5 问
Q1. 拍板权迁移到谁？
A：T0 治理委员会多签；T1 Policy Steward + Risk Steward 双签 + 委员会 review；T2 Policy Steward 单签 + GA check；T3 GA 自动。业务永远只是 proposer + appeal。
Q2. 团队边界怎么重划，谁失去核心权力？
A：策略失去拍板，得到 Policy Steward / Simulation Owner；算法失去推上线，得到模型治理 + 对抗鲁棒性；审核失去逐单判，得到 Boundary Curator + 申诉监督；治理权力跃迁；业务被边界化但获得 appeal 通道。
Q3. 治理是人、委员会还是 Agent？
A：三层——Policy-as-Code（机器）+ Governance Agent（受限）+ Human Committee（最终）。GA 硬上限：不能改红线、不能签自己 token、不能审自己 trace、不能跨域 approve。
Q4. 业务还能多少决策权？
A：定 KPI + 业务 SLA + 业务红线（举证责任 + 后果责任在业务）；冲突走自动 Pareto → Appeal → Committee；紧急通道 72h 业务保护，进风险负债账户。
Q5. 谁先消失，KPI 怎么改？
A：消失的是任务不是岗位（规则草稿、SOP 整理、标准化审核）；新 KPI——红线零突破天、跨域冲突减少率、Trace 抽检通过率、Risk-Adjusted Yield。
codex 挑刺：A8 治理三层结构最弱——具名 ≠ 真负责。补强：审计 KPI 独立 + 直达 CEO 汇报线 + 能力门槛硬约束 + 委员会容量监控防瓶颈。
Round 3 · 风险与红线 5 问
Q1. 每步合法但整体越权怎么拦？
A：Intent Envelope——声明 goal/scope/ceiling/detectionPlan/expiry；Risk Ledger 独立累计；End-of-Envelope 收束审计；Intent Auditor 双轨（结构 + 语言对抗微调）；owner 对漂移负责。
Q2. 攻击者污染 Memory Curator？
A：来源 Tier A/B/C/D + 越级拒写 + Provenance 图谱 + 反事实校验 + 衰减 + 双人验证 + 蜜罐 memory。
Q3. Governance Agent 被合理化绕过？
A：例外类型 enumerate + 例外预算账户 + 理由相似度检测（防换皮）+ 必带 detection plan + 默认 sunset 禁自动续期 + GA 输入净化（拒绝自由文本理由）。
Q4. 跨域级联事故先保什么？
A：硬优先级 红线 > T0/T1 Trace > 业务关键 > 次要 > 优化；状态机 NORMAL→DEGRADED→FREEZE→KILL→MANUAL；Incident Commander 切档，Agent 不允许自我切档回 NORMAL。
Q5. 人事变动 / 责任真空怎么防？
A：双备份 + 30 天 overlap + Vacancy >14 天自动收紧 + Time-bombed Authority + 知识非人化沉淀 + 双轨审计（内+外）。
codex 挑刺：A11 Intent Envelope 最弱——智能拆单可绕。补强：Super-Envelope 聚合 + 颗粒度审计联签 + 跨 owner 串谋检测 + Intent Auditor 双轨 + 组织 separation of duty 兜底。
Round 4 · 经济与路径 5 问
Q1. 全量成本账本与非线性热点？
A：跨域仿真 O(域²)、Trace 事故 burst 100x、新对抗 power-law、监管阶梯式跳。单位指标：每 1pp 漏放/误杀的边际控制成本 + 每条上线策略的 trace+sim+gov 成本。
Q2. 预算怎么分配，为什么不全投 Agent？
A：自治越高，控制类占比越高——L4 ≥1:1，L5 ≥1.5:1，超 L5 ≥2:1。Treasury Rule 自动调拨（红线突破 / break-glass / Trace lag）；按风险资本占用（EAD × LGD）定下限，不接受短期 ROI 砍预算。
Q3. 红线零突破不会激励"什么都不做"吗？
A：组合 KPI——红线零突破（门槛）+ 新对抗发现速度 + Risk-Adjusted Yield + Innovation Quota（允许可控失败）；区分健康回滚（沙盘+detectionPlan 命中）vs 无能回滚（计治理债）。
Q4. 哪些里程碑必须串行，哪些可并行？
A：串行 Event Store → Action Adapter → Policy-as-Code → Trace → 守门 → 受限可逆写 → CDIG → Memory Curator → Trace Auditor 独立汇报 → Risk Ledger → Intent Envelope → 外审 → 超 L5；并行 L1/L2 与基础设施 + 红队建设 + Boundary Curator + 业务红线 enumerate。
Q5. 半成品最危险阶段 + 禁止跳层？
A：L3.5 综合症——业务停不下来 + 治理 backlog 积压 + 监管反应放大。硬门槛见上节"禁止跳层"清单；跳层尝试本身记入治理债账户。
codex 终评：跨维度盲点见上节"三大盲点"；保命三件事 = 过门 + 留痕可撤 + 独立制动。其他能力都是在这三件事上长出来的增强层；没有这三件，越高级越危险。
红线：AI 可以更聪明地行动；但聪明行动开始伤害系统时，必须有人和机制让它停下来。
所有动作必须过门，所有动作必须留痕且可撤，所有动作必须有独立制动。
