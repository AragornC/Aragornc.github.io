L0 平台
人工驱动风控闭环。

人负责发现、分析、配置、执行、复盘和改进；AI 不参与认知和协作。
靠平台配置 + 人工协作。

机审、人审、判罚、监控、工单、文档分散运行，靠人串联上下文。
人汇总风险信号。

监控、红蓝军、监管、舆情、申诉入口分散，风险发现依赖人盯。
人跨系统查证。

日志、用户信息、人审记录、处罚历史要人工拼接，归因慢。
人判断根因。

根因依赖专家经验，容易停留在现象，难复用到下次风险。
人设计策略方案。

规则、模型、名单、阈值、人审口径互相影响，方案评估成本高。
人操作多个系统落地。

系统分散、操作复杂，配置、联调、上线、沟通都依赖人工推进。
人看报表和样本。

效果、误杀、漏放、申诉、业务影响分散，复盘滞后。
人沉淀规则和口径。

经验落在文档、会议和个人记忆里，标准化不稳定。
人把遗留问题带入下一轮。

遗留风险、待验证假设、未解决争议缺少结构化流转。
分散系统，人工串联。

机审、人审、判罚、监控、工单、文档各自运行，流程靠策略运营、算法、审核和工程人工串起来。
L1 模型
AI 写字进流程。

LLM 进入摘要、草稿、解释和报告环节；人仍负责判断、操作和拍板。
LLM API + Prompt 模板。

不接工具、不读生产数据、不写生产；所有事实由人提供，AI 只做语言加工。
AI 把分散信号写成简报。

入口仍分散；人粘贴监控、红蓝军、监管、舆情、申诉材料，AI 汇总成可读简报。
人拼证据，AI 改成段落。

跨系统查证和归因仍靠人；AI 只把人查到的零散事实串成可读叙述。
专家定根因。

关键原因仍由人判断；L1 不能让 AI 在事实判断上替代专家。
AI 起草策略说明。

策略同学口述目标，AI 写策略说明、规则注释、灰度方案和上线文档草稿。
人操作系统，AI 写沟通材料。

配置、联调、上线靠人跨系统手工操作；AI 只起草上线公告和跨团队沟通文案。
AI 把指标写成复盘简报。

人把效果、误杀、漏放、申诉数据给 AI，AI 总结成结构化复盘文本。
AI 起草规则注释和 SOP。

模型把人的经验改写成规则注释、审核口径、SOP 草稿，人 review 后入库。
AI 起草遗留清单。

模型把未解决问题、待验证假设、争议点整理成结构化 backlog，进入下一轮。
LLM 网关 + Prompt 资产层。

新增 LLM API 网关、Prompt 模板库、结构化输出 Schema、输出审计和人工确认流；机审、人审、判罚等系统保持 L0。
L2 知识
AI 带着知识做判断辅助。

模型不只写文本，还能引用规范、案例、口径和历史经验，给人提供带依据的候选判断。
RAG + 只读上下文接入。

建设知识库、案例库、规范库、向量检索、引用溯源和只读查询接口；仍不写生产。
AI 对齐历史风险。

把新信号和历史案例、监管规范、业务例外关联起来，输出风险方向和相似案例。
AI 组装只读证据。

从人给的上下文和只读查询结果里整理用户日志、审核记录、处罚历史和规则命中。
AI 给候选根因。

基于相似案例和规则口径提出根因候选，人确认最终判断。
AI 复用策略经验。

对照历史 patch、审核口径和灰度经验，生成候选策略方向和评估清单。
人执行真实动作。

AI 可给执行依据和注意事项，但配置、联调、上线、人审路由仍由人操作。
AI 对照历史解释效果。

把当前指标、申诉和样本与相似案例对比，给出误杀漏放和漂移解释。
AI 产知识入库草稿。

把确认过的案例、规则口径和审核经验整理成知识片段，等待人审后入库。
AI 标注遗留问题。

把未解决问题按风险方向、证据缺口、规则冲突和待补样本分类，进入下一轮。
知识服务层 + 只读连接器。

新增 RAG/向量索引、案例与规范知识库、Citation 引用、权限过滤、只读 Tool/MCP 查询；生产写口仍关闭。
L3 行动
AI 变成可执行工作单元。

Agent 围绕 Risk Case 自主跑多步，产证据包、任务、回放结果和策略草稿。
Agent Harness 承接任务循环。

引入任务状态、工具编排、Trace、沙箱和受限写工具；生产 commit 仍走治理。
Agent 自动建 Risk Case。

从风险信号生成 case，挂证据入口、影响面、优先级和待验证假设。
Agent 自主取证。

按 case 计划调用日志、特征、回放、人审记录等工具，形成可审计证据链。
Agent 提出根因 Proposal。

模型给出候选根因、证据引用和置信说明，但关键判断仍由人或治理节点确认。
Agent 起草策略 Patch。

自动生成规则草稿、特征建议、评估集补充和灰度方案，作为 proposal 提交。
Agent 做受限可逆动作。

可建任务、路由人审、准备灰度材料；封禁、判罚、生产配置不直接写。
Agent 自动跑评估。

触发回放、样本聚类、误杀漏放分析和影响面评估，生成检查报告。
Agent 生成沉淀草稿。

把证据链、策略草稿、评估结果写入 memory/skill draft，等待治理确认。
Agent 续接下一轮任务。

把未解决假设、失败样本、待补工具和待审批 patch 转成下一轮 case backlog。
Agent Harness + Tool Runtime。

新增 Risk Case 服务、工具注册表、状态机、Trace、沙箱、受限写工具和 draft memory；生产写入接治理管道。
L4 闭环
AI 跑完整风险闭环。

从发现、调查、提案、评估、灰度到复盘沉淀形成可追踪循环；人主要守治理门。
多 Agent 编排 + 治理流水线。

Risk Case 成为状态载体，Agent 之间通过 handoff/A2A 协作，所有动作进入 trace、eval、approval、rollback。
系统自动发现风险缺口。

监控、申诉、监管、舆情、红蓝军信号自动聚合成 case，并识别影响面、优先级和证据缺口。
多 Agent 并行归因。

调查、策略、审核、算法 Agent 分工取证，产出带引用、状态和 artifact 的因果链路。
AI 形成可审计根因结论。

多 Agent 交叉取证、自动反例搜索和 trace grading 通过后产出结构化根因；高影响或争议项进入治理复核。
AI 生成治理就绪 Proposal。

策略 patch、评估集、灰度计划、回滚条件和审批材料一起生成，进入治理管道。
AI 推进，治理 Commit。

低风险可逆动作自动执行；高影响判罚、封禁、生产规则变更必须经过 approval 和 rollback 兜底。
Trace 驱动自动验收。

系统持续跑回放、对照实验、误杀漏放分析、漂移监测和 trace grading，定位失败步骤。
经验自动沉淀成能力。

eval suite 自动验收通过的策略、样本、口径、失败模式进入 memory、skill 和规则版本库；失败或争议项进人审。
遗留项自动转下一轮。

未解决假设、异常样本、审批驳回和回滚原因自动生成下一轮 case，不靠人记。
Multi-agent Workflow + Governance Runtime。

多 Agent Orchestrator、A2A/Handoff、durable workflow、trace/eval、approval gate、gray release、rollback 和能力沉淀层共同承接。
L5 经营
AI 自治经营一个风险域。

AI 承担业务域/风险域的持续目标管理和结果优化，对风险、体验、成本和合规做长期权衡。
目标系统 + 自演进元循环。

Domain Agent 管目标、预算、实验、能力库和风险偏好；治理系统约束边界，防止自治越权。
AI 主动定义经营缺口。

围绕漏放率、误杀率、申诉率、成本、审核产能和合规红线，主动发现目标偏差和新型风险。
AI 跟踪长期状态漂移。

跨 case、跨策略、跨人审口径追踪相关性变化，提出对抗迁移、业务变化、策略副作用等候选解释。
AI 选择主攻方向。

在合规红线内，对风险收益、用户体验和审核成本做组合判断，提出下一阶段关键原因和优先级。
AI 制定风险域路线图。

规划实验、策略升级、模型迭代、红蓝军任务和数据建设；识别人审产能缺口，由运营管理者决策人力配置。
AI 调度资源，治理放行。

Agent 群执行实验和策略组合；影响用户权益、业务收入和合规边界的 commit 仍由治理系统放行。
AI 持续评估经营结果。

不只看单条策略效果，而是持续评估风险域 KPI、对抗成本、体验损伤和治理稳定性。
AI 更新能力与制度资产。

把成功策略、失败教训、技能和评估集版本化，成为下一轮自治能力；红线和治理策略由治理团队独立维护。
AI 自我设定下一轮目标。

根据经营结果和环境变化调整目标、预算、实验队列和能力缺口，形成持续自治循环。
Domain Goal Runtime + External Governance。

目标管理器、长期记忆、技能库、自评估循环、实验平台、资源调度和风险偏好引擎共同组成；治理策略引擎与生产红线均外置。

排布原则

这张表不是拆成六套流程，而是用同一条 PDCA 主链路观察 AI 能力逐层进入风控系统的位置。

1. 横轴

横轴固定为 PDCA：先定位问题，再归因和计划，执行后检查效果，最后固化并进入下一轮。

2. 纵轴

纵轴是 L0-L5 成熟度：同一套架构逐层长出 AI 能力。

3. 填表

架构承接不另起一套体系，而是解释这一层需要哪些系统能力来支撑同一条闭环。

L4/L5 证据边界

L4 主要来自已经进入工程实践的 agent 编排、持久执行、观测评估和治理护栏；L5 借鉴自我反思、长期记忆、技能库和开放式学习研究，但在风控生产中必须保留治理红线。

工程依据

OpenAI Agents SDK、Google A2A、LangGraph 和 Anthropic agent patterns 支撑多 Agent、handoff、trace、eval、durable workflow 和 human-in-the-loop。

研究依据

Reflexion 证明语言反馈和 episodic memory 可改善多轮 agent 表现；Voyager 展示自动 curriculum、技能库和环境反馈驱动的 lifelong learning。

治理依据

NIST AI RMF 强调在 AI 系统设计、开发、使用和评估中纳入可信与风险管理；所以 L5 自治经营仍不能绕过生产红线。

红线：AI 可以提出 proposal、运行评估、推动闭环和自治经营，但高影响生产 commit 必须经过治理管道。
