JVM 运行时内存结构 · 单步白盒

JVM 跑你的程序时,在内存里划出的几块"地盘",各存什么、谁共享谁私有。← 知识地图 · Java › 内存模型与运行机制

😌 零基础口径,每个名词都拆。 先记一句话:JVM = Java 虚拟机,就是真正"跑"你 Java 程序的那个引擎(你写的代码先编译成它能懂的指令,再由它执行)。它执行时要用内存,就把内存切成下面几块,各管各的。

① 先认地图:5 块内存区,各存什么

两个大色:🟫 金边=线程共享(大家一起用) · 🟦 蓝边=线程私有(每条流水线各有一份)。
线程是啥?= 程序里一条独立执行的"流水线"。一个程序可以同时跑好几条线程(比如一边下载一边显示)。先记到这,细节留到「并发」模块。共享=所有线程看同一份;私有=每条线程各有各的、互不干扰。
堆 Heap线程共享
存所有 new 出来的对象和数组。是最大的一块,也是垃圾回收(GC)主要打扫的地方(GC 是下个模块)。
类比:一个大仓库,谁(哪条线程)都能往里放货、取货。
方法区 / 元空间线程共享
存"类长什么样"的信息:类的结构、方法的代码(字节码)、常量、静态变量(static)。Java 8 起这块叫元空间(Metaspace),放在堆外的本地内存里。
类比:图纸库,存每一种"产品(类)"的设计图;造对象时照图纸来。
虚拟机栈 JVM Stack线程私有
每条线程一个。每调用一个方法,就压一个"栈帧"进去,栈帧里放这个方法的局部变量和对象引用。方法返回就弹出。
类比:你个人的草稿本,一页算一个方法的演算;算完一页(方法返回)就撕掉。
程序计数器 PC线程私有
每条线程一个、很小。只记一件事:这条线程当前执行到哪条指令了。线程切来切去,靠它记住"我刚才走到哪"。
类比:看书时的书签,夹住"我读到第几行"。
本地方法栈线程私有
跟虚拟机栈几乎一样,但专门给 native 方法用——就是底层用 C/C++ 写的、不是纯 Java 的方法。平时少碰,知道有这块即可。
类比:草稿本的"外语版",给非 Java 的方法记账。
对象=用 new 造出来的实例(比如 new 一个"用户")。引用=一个指向对象的"门牌号/地址",不是对象本身。基本类型=数字、true/false 这种最朴素的值(int、boolean…),不是对象。这三个词下面会反复用到。

③ 多线程时:谁各有一份、谁共用一份

同一个程序跑两条线程时,内存是这样分的——栈和 PC 每条线程各一份(私有),堆和方法区两条线程共用(共享):

🧵 线程 A 的私有

· A 自己的虚拟机栈(它的栈帧)
· A 自己的程序计数器 PC
· A 自己的本地方法栈

🧵 线程 B 的私有

· B 自己的虚拟机栈(它的栈帧)
· B 自己的程序计数器 PC
· B 自己的本地方法栈

📦📐 A、B 共享(同一份)

· 堆 Heap(两条线程 new 的对象都放这个大仓库,所以它们能访问到同一个对象——这也正是「并发」问题的根源,留到那个模块)
· 方法区/元空间(类的图纸只有一份,大家照同一份)
💡 记忆口诀:"栈和计数器,人手一份;堆和方法区,大家共享。" 私有的随线程生灭,共享的活得久(尤其堆里的对象,要等 GC 来清)。
下一步预告:你在上面看到 main 结束后,堆里那个 User 对象还赖着不走(没人引用它了却还占着内存)——谁来清它?那就是下一个白盒 「垃圾回收 GC」的活。而"类的图纸怎么进的方法区",是 「类加载」的活。这俩接着做。
