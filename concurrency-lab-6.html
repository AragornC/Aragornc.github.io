线程的一生:6 种状态怎么转

基础

Java 里一条线程任意时刻处在 6 种状态之一。点下面的事件按钮,让这条线程在状态图上走起来(RUNNABLE 是中心枢纽,几乎所有状态都从它出发、又回到它):

当前状态:NEW

这不是讲故事——真跑一下,让程序在不同时刻打印自己的 getState():

▶ 抓现行:NEW → TIMED_WAITING → TERMINATED无特殊参数
三个时刻打印出三种真实状态
▶ 抓 BLOCKED:一个线程想进的锁被 main 占着无特殊参数
打印出 BLOCKED
📌 排查线上卡顿的关键:jstack 打印每条线程的状态。一堆线程卡在 BLOCKED → 八成是锁竞争激烈或死锁;卡在 WAITING/TIMED_WAITING → 在等条件/等返回(比如等数据库、等下游)。⚠️ 注意 Java 的 RUNNABLE 把"正在 CPU 上跑"和"等 IO"合并了,所以一个在等网络的线程也显示 RUNNABLE,别被骗。
②

CompletableFuture:把异步任务串成流水线

进阶

手写 new Thread 拿结果很痛苦(还得 join、还得用变量传值)。CompletableFuture 让你像搭积木一样组合异步任务。三个最常用动作:

方法意思
supplyAsync(任务)丢一个任务到后台线程跑,立刻返回一个"未来会有结果"的凭证
thenApply(结果 -> 加工)上一步结果出来后,接着串行加工它(流水线下一道工序)
thenCombine(另一个, (a,b)->合并)等两个并行任务都好,把结果合并到一起

下面这个:查价格(500ms)和查库存(500ms)同时开跑,两个都好了再算总价。串行要 1 秒,并行只要半秒:

▶ CompletableFuture:两个慢任务并行 + 合并无特殊参数
看耗时 ≈ 500ms(不是 1000ms)——两个任务真并行了
📌 记住:CompletableFuture = "异步任务编排器"。thenApply 串(一道接一道)、thenCombine 并(等齐再合)、还有 thenCompose(用上一步结果再发起新异步)、exceptionally(出错兜底)。它默认用一个公共线程池跑——生产中建议自己传线程池进去(还记得第 3 课的教训吗?别用默认的)。
